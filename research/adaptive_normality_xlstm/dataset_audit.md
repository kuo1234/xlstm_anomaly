# Dataset and protocol audit

Problem A (new-machine transfer) and Problem B (new-normal over time) need different evidence. A dataset that contains a train/test distribution shift does not automatically contain ground truth for benign regime changes.

## Dataset suitability

| Dataset / resource | Potential use | What it can support | What it cannot establish by itself | Audit / split requirement |
|---|---|---|---|---|
| **SMD**: [official OmniAnomaly repository](https://github.com/NetManAIOps/OmniAnomaly) | Problem A, same-D machine transfer | 28 server machines, each 38 dimensions; normal training interval and labeled test anomalies; useful controlled leave-machine-out transfer with identical input dimensionality | Legitimate new-normal labels, mode semantics, or anomaly-versus-benign-shift ground truth. Train/test shift alone is not benign drift. | Pin exact machine/channel mapping and order; hold out complete machine identities from pretraining; target-normal warm start must count unique raw timestamps or duration, not highly overlapping W64 windows. Split later target anomalies chronologically. Audit zero/near-zero channels and per-machine metrics. |
| **HAI / HAIEnd**: [official dataset repository](https://github.com/icsdataset/hai) | New-machine/variant transfer with operational context; later Problem B candidate | Realistic HIL ICS with boiler, turbine, water treatment and control logic; versions include normal runs, attack runs, attack annotations; HAIEnd adds internal control tags/graphs. Normal data use different operating situations. | It does not label every normal-mode transition as a new-normal event paired against semantically matched persistent faults; attack-centric labels are not a complete benign-drift oracle. | Treat versions and processes as domains, not interchangeable machines. Determine which controller tags/setpoints are observable at decision time. Use control context for evaluation and possibly gating only if available in intended deployment. |
| **SWaT**: [iTrust dataset characteristics](https://www.sutd.edu.sg/itrust/itrust-labs/datasets/dataset-characteristics/swat/) | Anomaly baseline; later process-context study | 51 sensors/actuators; 7 days normal and 4 days with 41 attacks in the cited collection; continuous control-process records. | One testbed and a short protocol; mostly binary normal/attack periods, not independent labels for legitimate new normal versus a persistent attack. Different process stages are not automatically separate machine identities. | Use the provider's version and label timing. Do not call attack-period variation benign drift. Preserve chronological run/event groups. |
| **WADI**: [iTrust/release description](https://www.sutd.edu.sg/itrust/itrust-labs/datasets/dataset-characteristics/wadi/) | Anomaly baseline; possible external process-mode covariates | A water-distribution testbed with about 123 sensors/actuators; normal and attack periods and attack scenarios. | A single site/testbed; no general mode-labeled benign drift protocol. High dimensionality does not mean arbitrary-D transfer. | Version-specific channel count/metadata matters. The common description is 14 normal days and 2 attack days; use original release manifests. |
| **MSL / SMAP**: [OmniAnomaly data documentation](https://github.com/NetManAIOps/OmniAnomaly) | Cross-domain anomaly baseline, not first transfer study | NASA mission telemetry with labeled anomalies, multiple channels/entities. | Heterogeneous channel semantics; no simple shared D or aligned machine channels, and no explicit benign regime vs fault annotations. | Treat each telemetry entity as distinct. A universal shared model needs explicit channel-set handling and a separate claim. |
| **PSM**: [benchmark description](https://github.com/NetManAIOps/OmniAnomaly) | Detection baseline / shift stress test | Multivariate server metrics with anomaly labels. | Does not establish a machine-pool target-normal curve or semantic new-normal labels. | Verify dataset version; published dimensionality varies across wrappers (commonly 25/26); do not assume compatibility with SMD. |
| **AnoShift**: [NeurIPS D&B 2022](https://proceedings.neurips.cc/paper_files/paper/2022/hash/d3bcbcb2a7b0b4716bf24ce4b2ea8d60-Abstract.html), [code](https://github.com/bit-ml/AnoShift) | Temporal distribution-shift robustness, drift-stratified evaluation | Ten-year Kyoto-2006+ network-traffic benchmark with IID/NEAR/FAR temporal splits; normal/attack labels and naturally changing traffic. | The year-wise input shift is not labeled as safe-to-absorb normality. A new traffic pattern may be benign, adversarial, or unknown. | Evaluate recall/FPR under temporal shift without promoting automatically. It supports “shift robustness,” not “benign new normal detected.” |
| **M2N2 protocol datasets**: [paper](https://ojs.aaai.org/index.php/AAAI/article/view/29210) | Reproduce/compare a new-normal TTA baseline | Established baseline for test-time self-supervised updating under distribution shift; includes common MTSAD benchmarks such as SMD, SWaT, WADI and NASA telemetry. | Evaluation labels generally distinguish anomaly from normal, not semantic approval of each shifted regime. | Reproduce only after dataset versions, windowing and target access rules are matched. Its shift protocol is useful for M5, not a full semantic B oracle. |
| **TSB-AD-M / TSB-AD-U**: [NeurIPS 2024 benchmark](https://thedatumorg.github.io/TSB-AD/) | Source-native detector viability and anomaly-type stratification | Larger, curated anomaly benchmark; can stratify point/segment anomalies and compare simple detectors. | A benchmark anomaly label does not label whether a persistent shift is a legitimate operating mode. Broad benchmark aggregation can hide domain-specific failures. | Use as an external detector stress test, not as the only target-transfer study or B dataset. Freeze benchmark split/version and primary metric. |
| **StrAD / TSB-drift**: [StrAD code](https://github.com/magaliparrino/StrAD) | Online streaming drift stress | Stream-oriented benchmark and drift tags over real time series can expose update behavior. | Statistical concept drift is not equivalent to benign normality; tags do not by themselves distinguish a safe mode from a persistent anomaly. | Inspect stream annotations and causal evaluation semantics before inclusion; keep detection labels separate from change tags. |
| **NoBOOM**: [NeurIPS D&B 2025](https://proceedings.neurips.cc/paper_files/paper/2025/hash/96f8c5e879c339dae55e6c2188b02a33-Abstract-Datasets_and_Benchmarks_Track.html), [OpenReview paper](https://openreview.net/pdf?id=qiLboR0ocm) | Strong industrial anomaly validation; candidate for contextual mode analysis | Labeled production, laboratory and pilot chemical-process data; operational documentation and event detail for some components. | Its anomaly labels and operating descriptions do not automatically furnish a fully paired “benign new mode versus persistent fault” stream for every process. Some industrial details are restricted. | Audit each component's accessible mode/setpoint metadata and timestamps. Do not assume all components are multivariate/time-aligned or legally shareable. |
| **Smart-building drift/attack study data**: [ACM E-Energy 2026 paper](https://doi.org/10.1145/3744255.3811742), [code](https://github.com/illinois-arcs/Drift-Aware_AD) | Most direct reviewed Problem B dataset/protocol | Real building management/HVAC data with normal operation, labeled normal drift and attack cases; chronological evaluation; cross-floor study. The method maps gradient-profile clusters with 100 labeled examples per class and selectively updates on normal/drift. | It is not an unlabeled or normal-only target adaptation protocol; paper scope is a specific building environment. Need verify the raw dataset access/license and that persistent attack episodes are represented with adequate duration. | Strongest current candidate for a direct baseline/reproduction if the released data are usable. Compare its limited class-labeled protocol separately from a confirmed-normal-only setting; inspect event labels and deployment-available inputs before selecting. |
| **Batch Distillation**: [dataset paper/data](https://pmc.ncbi.nlm.nih.gov/articles/PMC13044305/) | Candidate for normal-only transfer across process settings and controlled fault comparison | 119 lab experiments across mixtures/operating conditions; many anomalous runs have paired fault-free runs; detailed expert metadata and fault causes. It is a promising paired design. | Separate batch runs do not automatically demonstrate online transition to a benign new mode or recurring old normal within one deployed stream. Operating conditions need a semantic mapping and run-level split. | Split by experiment/run and operating point; use confirmed fault-free paired runs for target sample curves. Check usable dimensions, cadence, warm-up phases and whether an allowed-mode label exists. |
| **DAYPSCI**: [Data in Brief 2026](https://www.sciencedirect.com/science/article/pii/S2352340926006931) | Controlled CPS fault/event study and context-aware evaluation | PLC-controlled station with real hardware/digital twin, event-based logs, scan/event order, runtime process-state (e.g. GEMMA) context, and injected sensor/actuator faults. | Irregular event records are not a dense fixed-cadence sensor stream. Process states do not necessarily label a persistent benign regime transition. | Could test context and fault causality, but resampling/event-time modeling is a separate choice. Use fault activation and observable manifestation times separately. |
| **Synthetic controllable stream** | M2/M3/M5/M6 causal mechanism checks | Can independently control abrupt/gradual/recurrent benign shifts, transient/persistent anomalies, contamination and semantic context, including observationally identical benign/anomalous pairs. | Does not substitute for industrial validation or prove real deployment behavior. | Publish generator equations, seeds and event semantics; use as a kill test and identifiability demonstration, not sole evidence. |

## Problem A recommendation

SMD is the lowest-friction controlled starting point because its machines share D=38, but it does not prove channel semantics align. A machine-held-out split should first freeze a documented channel map. Pretraining excludes every target-machine value, including unlabeled test values. For each target, the few-shot sample should be a contiguous, independently confirmed-normal prefix or disjoint blocks with an explicit raw-sample/time budget. The later evaluation suffix remains untouched until final scoring. Results should be macro-averaged over target machines and also shown per machine.

HAI and WADI/SWaT are plausible later robustness checks, but their different sensors and process semantics make them poor substitutes for same-D controlled transfer. Arbitrary-D universal transfer should stay out of the first study.

## Problem B recommendation

SMD and AnoShift do not satisfy the required semantic ground truth. M2N2 benchmarks show performance under shifted distributions, not necessarily whether a shift is acceptable. Prefer data sources with process metadata and paired fault-free / fault runs. Batch Distillation, NoBOOM, HAI/HAIEnd and DAYPSCI are candidates to audit, not pre-approved datasets. Before claiming Problem B, inspect raw metadata, identify transitions and their authoritatively allowed status, confirm persistent-fault labels, and establish a causal context channel that will exist at deployment. If no candidate dataset offers both labels, narrow the claim to “reduces false positives under measured distribution shifts” and do not call it safe new-normal discrimination.

## Arbitrary dimensionality

Not a first-study requirement. SMD permits a controlled same-D transfer question. Future options are channel-independent encoding, a permutation-invariant channel-set encoder, explicit mask/padding with missingness, a learned latent adapter, or metadata-aware channel embeddings. Each changes the scientific task and introduces channel-semantic assumptions; test only after the same-D transfer claim survives.
