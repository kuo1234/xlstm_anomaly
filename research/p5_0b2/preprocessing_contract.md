# Preprocessing contract

## Purpose

Freeze preprocessing behavior for the v0.7.1-referenced generic dense AE / per-row RMSE detector. EFD's generic package supports a configurable pipeline; the project must use an explicit, serializable pipeline and must not rely on package defaults that filter or transform columns implicitly. This contract is pre-label: method development and every fitted preprocessing statistic use SOURCE only. No TARGET values, target missingness, or target score distributions may be inspected to define or alter the pipeline.

Reference implementation context: [`DataPreprocessor`](https://github.com/AEFDI/EnergyFaultDetector/blob/ced470e1386066931bad32f3cb6e24bac9c5bb89/energy_fault_detector/data_preprocessing/data_preprocessor.py), [`Imputer`](https://github.com/AEFDI/EnergyFaultDetector/tree/ced470e1386066931bad32f3cb6e24bac9c5bb89/energy_fault_detector/data_preprocessing), [`Scaler`](https://github.com/AEFDI/EnergyFaultDetector/tree/ced470e1386066931bad32f3cb6e24bac9c5bb89/energy_fault_detector/data_preprocessing), and [`RMSEScore`](https://github.com/AEFDI/EnergyFaultDetector/blob/ced470e1386066931bad32f3cb6e24bac9c5bb89/energy_fault_detector/anomaly_scores/rmse_score.py). The behavior below is the project protocol choice, not a claim that the upstream defaults implement it.

## Input schema and feature eligibility

- Input to the detector is a timestamp-indexed row of sensor measurements. Timestamp is identity/order metadata; it is not an AE feature unless a later sealed source-only procedure explicitly specifies otherwise. No target-derived calendar or event feature may be engineered.
- The ordered input feature schema is frozen in [`feature_projection.json`](feature_projection.json). For each eligible stratum, start with its committed `automated_common_feature_intersection` in P5-0B1R `schema_audit.csv`, sort the retained names in ASCII lexical order and keep only names ending in `_temperature`, `_temperature_setpoint`, `_room_temperature_setpoint`, `_meter_flow`, `_meter_heat_power`, `_control_valve_position`, or `_control_valve_position_setpoint`; discard names containing `__duplicate_`. Names ending in `_meter_energy` or `_meter_volume` are explicitly excluded. The exact resulting names are listed per stratum in the projection manifest, which pins both structural input hashes. Before projection, D values in ASCII lexical stratum order were `[10, 13, 10, 14, 10]`; after excluding energy and volume meter fields they are `[8, 11, 8, 12, 8]`. D is recomputed from this reduced ordered projection. No CounterDiffTransformer or value-based reconsideration is permitted. This explicit positive name rule removes categorical, text, boolean, mode/status, fault/event, identifier, label, union-only, and otherwise unapproved columns before detector input. Status fields may not be used as features or as a target-time filter.
- Raw ingestion projects by selecting the frozen ordered feature names from the raw header. Raw columns outside that list, including union-only and excluded common-intersection fields, are ignored before detector-schema validation. After projection, require the exact ordered names and schema hash: a missing required field, duplicate raw header, duplicate projected name, order/hash mismatch, or failed numeric cast is fail-closed. Numeric usability of SOURCE fit values is checked using SOURCE only; the same schema applies to every entity and is frozen before target-prefix adjudication. Never intersect, prune, or reorder in response to TARGET values or missingness.
- Parse source measurements as float64 for preprocessing statistics, then cast the transformed model input to float32. Reject failed casts and duplicate feature names. `NaN` is the only imputable missing value; any positive/negative infinity or nonnumeric cell invalidates that row. No value clipping, angle conversion, counter differencing, timestamp encoding, category encoding, or feature selection is introduced unless explicitly represented in the frozen SOURCE-only candidate grid and selected before the method seal. The initial primary contract includes none of those implicit domain-specific transforms.

## Fitting and transform behavior

1. Fit per-feature medians on finite SOURCE training observations only. Use NumPy float64 type-7 median semantics; then impute NaNs in those same fit rows and fit per-feature mean and population standard deviation (`ddof=0`) in float64. Save exact fitted parameters, feature order, dtype, and artifact hash.
2. Use a deterministic per-feature imputer and scaler whose definitions and tie/rounding behavior are version-pinned in the implementation manifest. Candidate choices may be compared only under the sealed source-only procedure. No statistics are calculated from TARGET rows.
3. In all validation and target inference, call the saved transform only. No fit, refit, partial-fit, adaptive imputation, adaptive scaling, target-specific column pruning, or target-prefix normalization is permitted.
4. Preserve each raw observation row and its index through preprocessing. Missing feature values do not remove rows or change raw look counts.

## Fail-closed missingness rules

- SOURCE-only feature screening must reject any selected feature with no finite fit observations in the source training fold. If the fixed stratum schema cannot be supported consistently across the predeclared SOURCE training procedure, the stratum is `SOURCE_MODEL_NOT_EVALUABLE`; do not silently drop a feature only for selected entities or merge strata.
- A source feature with `std <= 1e-12 * max(1, abs(mean))` fails the stratum. If the fixed schema cannot be supported consistently across the frozen folds, do not remove the feature or merge strata.
- At transform time, any required feature absent from the frozen schema, duplicate projected feature, nonnumeric value, or schema-order/hash mismatch is an invalid row/schema event. Unselected raw columns have already been discarded by the fixed projection and do not enter this check. Do not infer a substitute feature or use a target-derived schema.
- A partially missing row may be imputed only under the fixed source-fitted imputer. An all-missing row across the full fixed feature schema is invalid and receives no score. For an individual feature that is all-missing across SOURCE fit observations, fail the stratum as above; never fill it with a constant selected using target data.
- After imputation and scaling, any non-finite component makes the row invalid. Do not silently coerce infinities to zero, drop the row, or pass non-finite values to the AE. Emit an invalid-score reason code without raw values.
- Invalid rows still count as raw observations toward looks `144, 288, 576, 1152, 2304` and the 64-day acquisition budget. The readiness contract determines the minimum valid-score support at each look. If support is insufficient at a look, outcome is `NOT_READY`; unresolved insufficiency at raw observation 2304 is never-ready/commissioning failure, with no extension.

## Scaler and score boundary

The scaler is fitted only on SOURCE training data and is part of the frozen model artifact. The AE reconstruction error is computed in that fixed preprocessed feature space. The detector score is unweighted row-wise RMSE over the fixed ordered schema; it is not standardized using target residuals, per-target feature statistics, or target quantiles. Compute residual differences and row mean/square root in float64 from float32 input/reconstruction. Readiness calibration can update only the distinct threshold state specified in `threshold_contract.md`; preprocessing, model, and score remain immutable.

## Provenance requirements

Record the source-only schema selection rule and selected ordered names/hash; source fit partition provenance hash; imputer/scaler definitions and fitted parameter hashes; source code/dependency versions; numeric dtype; transform implementation hash; and all invalid-row counts by reason. During method development, logs and artifacts must not expose target identifiers, timestamps, per-target missingness, feature values, or score values. TARGET prefix eligibility is a later, separate, sealed operation and cannot revise these decisions.
