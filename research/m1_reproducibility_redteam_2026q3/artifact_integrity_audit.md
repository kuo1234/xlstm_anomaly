# Artifact integrity and provenance audit

**Audited M1 commit:** 2eda60d024d2a9149d62de5161ca76916a085942

## Verdict

Artifact hashing and pre-label sealing are substantial and fail closed for many ordinary mutation and partial-write cases. However, the Stage-1A source SHA is not guaranteed to identify the exact code bytes that executed if the worktree was dirty. This is a REPRODUCIBILITY_RISK. The broader label-access-history contradiction is a BLOCKER described in data_leakage_audit.md.

## Positive controls observed

1. Stage-1A records Git HEAD and requires the amendment and selected-machine list to be committed before running. It records hashes for checkpoints, scaler, calibration arrays, score arrays, and per-arm run records. Evidence: scripts/adaptive_normality_m1_stage1a.py:401-451, 459-479.
2. Stage-1A validation recomputes parameter counts, checks checkpoint/run hashes, verifies train/test observation hashes, checks exact score inventories/timestamps, and re-derives q=.99 higher thresholds from sealed calibration data. Evidence: scripts/adaptive_normality_m1_stage1a.py:229-290.
3. The Stage-1A metric path verifies that run records and artifacts are committed and byte-identical to the pre-label seal commit. It checks that source_commit is an ancestor of that seal. Evidence: scripts/adaptive_normality_m1_stage1a_metrics.py:153-199.
4. Score artifact publication uses create-if-absent hard links and refuses an existing artifact or manifest, reducing overwrite by a racing writer. Evidence: scripts/adaptive_normality_m1_scores.py:202-234; Stage1B-R helpers at scripts/adaptive_normality_m1_stage1b_r.py:78-107.
5. At AUDITED_M1_SHA the tracked tree contains no Stage1B-R result directory or score/execution seal. The feasibility note says it was frozen before model execution at research/adaptive_normality_m1_smd/stage1b_gate_feasibility.md:3-6. This audit did not inspect active or untracked runtime outputs, so it makes no claim about live execution state.

## REPRODUCIBILITY_RISK: HEAD does not seal a clean Stage-1A tree

run_stage1a() captures git rev-parse HEAD and checks only that the amendment and machine list are committed. It does not require a clean worktree or record hashes for the runner, training/scoring modules, untracked files, or source diff. Evidence: scripts/adaptive_normality_m1_stage1a.py:459-470.

The metric verifier proves the recorded source commit is an ancestor of the pre-label commit, not that executed bytes equal that commit. Evidence: scripts/adaptive_normality_m1_stage1a_metrics.py:168-187. A modified tracked module or shadowing untracked module could therefore produce artifacts attributed to clean HEAD. This is a design gap; no evidence was found that historical Stage-1A execution actually used dirty code.

The pre-label and post-metric commits are bcdd348e1d6609f4af357506d1c6b328eaac638a and 2792b1ee2b74bec97c6e70996a808ea1f3bba974. The diff between them adds the gate, access log, and result artifacts, not runner or protocol changes. Subsequent changes to AUDITED_M1_SHA add the Stage1B-R feasibility note and implementation/tests, not edits to the frozen Stage-1A method. This narrows the concern but does not replace a recorded clean execution tree.

## Provenance statement strength

The access log, execution JSON flags, and report statements are generated by the process under audit. No OS file-open log, container mount trace, or independent access monitor is committed. Therefore the exact evaluator read set is self-reported; test_labels_read=false is not evidence that no unrelated process previously opened labels; and the all-28 parsed-label inventory is affirmative evidence of prior project-level label exposure.

## Stage1B-R source binding

The Stage1B-R runner checks that a list of source paths in the supplied repository are committed and records that repository’s HEAD. Evidence: scripts/adaptive_normality_m1_stage1b_r.py:520-543. Python functions execute from already-imported modules and dependencies. If code imported from checkout A is called with repo=B, checks and recorded SHA can describe B while A’s loaded functions execute. This only affects non-default cross-repository API use; no Stage1B-R execution exists at AUDITED_M1_SHA. See concurrency_resume_audit.md.
