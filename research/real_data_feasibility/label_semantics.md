# Label semantics and estimand boundary

An anomaly point label is **not** a benign-drift label. A train/test shift statistic is **not** an independently annotated change point. An attack schedule is **not** a benign regime. Source-native below means measured/annotated on the released series, not that attacks were spontaneous (industrial testbeds intentionally stage attacks).

| Source | Per-row anomaly? | Benign change? | Normal / drift / anomaly / overlap distinguishable? | Consequence |
|---|---|---|---|---|
| Original SMD 1-4, 2-1, 1-8 | Test row `0/1` | No drift column | Only normal versus anomaly; empirical shift has no onset truth | Standard TSAD and M2N2 new-normal comparison only. |
| Telemanom P-15/T-3 | Expert anomaly **test intervals**, not CSV point vector | None | Only anomaly interval; neither timestamp nor drift interval in `.npy` | Future expansion of interval labels requires a frozen endpoint rule. |
| SWaT/WADI/HAI | Staged attack flag in test, HAI `Attack` per second | None | Attack versus nonattack; nonattack is not certified benign-drift | Industrial anomaly validation, not exact drift-vs-anomaly. |
| Yahoo A1 | Labeled real-series points | None | Anomaly versus other; no drift clock | Univariate shift stress only. |
| CreditCard | Fraud `Class` per irregular transaction | None | Fraud versus legitimate; no drift | Low-shift transaction control, not regular telemetry. |
| AnDri arXiv v2 ECG/IOPS | Source anomalies, composition uncertain | Injected segment transitions and generated schedules | A generated drift interval could be paired with anomalies if exact artifact/schedule is recovered; mixed rules unverified | Semi-synthetic stress; not native drift ground truth. |
| AnDri arXiv v2 Elec/Weather | Injected scaled anomalies | Natural variation, no independently frozen drift intervals located | Anomaly labels exist in experiment conceptually; benign drift/overlap undefined | Cannot score exact synthetic four-way estimand. |
| AnDri current Climate | Derived `heavy`/threshold flags | Natural seasonal pattern, no drift interval | Thresholded precipitation versus other | Threshold-defined event, not native anomaly-vs-drift annotation. |
| AnDri current Traffic | Per-feature EWMA/calendar-derived `_label` flags | `is_event`/season indicators, no adjudicated legitimate change intervals | Neither four-way truth nor expert anomaly truth | Useful only as rule-derived semantics with rule auditing. |
| AnDri current SMD/SWaT | Original anomaly/attack labels, possibly cropped | None | Binary anomaly/attack only | Do not infer drift from AnDri algorithm predictions. |
| AnDri current Sensor / `real iot` | Separate `anomaly_point` and `anomaly_pattern` per row; loader uses OR | `change_point` per row, **onset marker**, not duration | In the acquired files 3 marked changes (2+1), all with both anomaly flags 0 at the marker; no explicit drift-active or mixed class | The one promising public source for *change-onset versus anomaly* discrimination, but it is univariate, sparse, irregular, and cannot directly reproduce drift-active-window/mixed synthetic estimand. |
| TSB-drift CD=1 | Per-row anomaly in each benchmark series | Series-level CD/type tag only | No per-timestamp drift windows | Historical provenance STOP remains; no label invention. |

[AnDri v2](https://arxiv.org/pdf/2506.15831v2) describes CanGene/MOA injection for ECG/IOPS and multiplicative anomaly injection for Elec/Weather. The [later extended manuscript](https://www.cas.mcmaster.ca/~fchiang/pubs/andri.pdf) asserts that experts manually marked Sensor drift and anomaly points; this is **paper attribution**, and both actual `real iot` files contain the named columns. The [upstream source repository](https://github.com/kimhungGCZ/anomaly_dataset) supplies identical bytes but no inspected independent labeling manual/adjudication trail. It is therefore fair to describe *paper-asserted change-point/anomaly labels*, not independently established expert drift-active ground truth. Row 350 and 1172 in file 1, row 581 in file 2 have `change_point=1` and anomaly flags zero; those rows do not define how long the new legitimate regime lasts. Unmarked rows after a change cannot automatically be treated as drift-positive, and an absent overlap flag is not proof overlap cannot occur.

Under the [M0 protocol](../../reports/m0_protocol.md), real data can validate anomaly measurement/admission when source identities, splits and labels qualify. H2/H3/H4a **drift class**, post-shift latency and mixed-stratum labels are N/A until independently defined and sealed. Even the IoT onset markers do not give the synthetic first-256-sample drift-active definition or the stable-new-normal distinction. A future *separate* onset-focused question could be proposed with explicit uncertainty, but it would not be the exact synthetic estimand. Never use AnDri's predicted model change decisions as ground truth.
