# M0-E prior-art audit: frozen-weight recurrent-state intervention

Audit date: **2026-10-05**. Scope: read-only literature investigation for Issue [#22](https://github.com/kuo1234/xlstm_anomaly/issues/22), not an experiment authorization. No training, dataset/performance experiments, or empirical novelty tests were run. Search terms, source URLs, evidence tiers and access failures are in [the source ledger](provenance/prior_art_sources.json).

## Decision

**REFRAME; novelty remains unresolved.** “Adapt memory rather than weights,” “use prediction errors to control recurrent memory,” and “reset stale state during continual inference” are not defensible standalone novelty claims. Strong predecessors exist for all three. The strongest newly identified application-level threat is **Residuals Stationarity Intervention (RSI, 2026)**: a time-series anomaly detector that changes SSM hidden states after inferred change. **HSO (2021)** already optimizes inference-time hidden states with frozen model weights and explicitly separates pre-update scoring from later correction. The **Leto workshop manuscript** extends test-time memory optimization to multivariate forecasting and anomaly detection. These collisions survive even if xLSTM is substituted for the original backbone.

This is a bounded primary-source audit, not an exhaustive systematic review. Full-text availability means method sections were inspected, not that every appendix, proof, implementation or result was verified. No claim about comparative accuracy is made. Unresolved source identities and inaccessible articles remain blockers to a strong novelty claim.

## What is being adapted?

Use a deployment-state ledger rather than the ambiguous word “memory.” Let `theta` be learned persistent parameters, `s_t` the recurrent execution state, `B_t` an external bank, `n_t` normalization statistics, and `q_t` detector/controller state.

| Mechanism | Changed object | Distinction required in a future proposal |
|---|---|---|
| Ordinary recurrence | `s_t = F_theta(s_(t-1), x_t)` | Frozen weights already permit changing state; this alone is not adaptation novelty. |
| Parameter adaptation | `theta`, including adapters or learned offsets | A frozen backbone can coexist with trainable adapter parameters. |
| State reset/reinitialization | `s_t` replaced by zero, a learned initial state, or replay-derived state | A post-training controller and its intervention policy must be distinguished from a native forget gate. |
| State optimization | Gradient/filter correction of `s_t` with `theta` fixed | Record loss, causal target availability, optimizer state, and whether the original output is immutable. |
| State bank/restoration | Stored execution-state tuples selected into `s_t` | External examples, embeddings, prototypes or saved model weights are not execution-state restoration. |
| Normalization adaptation | `n_t` or normalization affine parameters | Statistical transformation changes can mimic drift recovery without fixing recurrent history. |
| Classical filtering | Posterior state mean/covariance updated by innovations | Inference-time latent-state correction is old; a neural state controller must establish what exceeds this principle. |

An xLSTM state restoration must be compatible with the exact architecture and normalization coordinates. Restoring only a displayed hidden vector while leaving other recurrent, normalization, stabilizer or convolution state inconsistent is a different and potentially invalid operation. This is an audit requirement, not a verified implementation result.

## The restoration-bank gap is not a novelty finding

Searches for recurrent/hidden-state banks, reinitialization, restoration and recurring drift did not yield a verified exact match that stores and restores a complete frozen xLSTM execution tuple for unlabeled TSAD. This is a **search result limitation**, not evidence that the combination is new. MemDA/BOCPD already weaken generic “remember/reuse contexts” framing, and the three unresolved leads prevent a clean exclusion argument. Checkpoint restoration is also an ordinary engineering operation; publication value would need to reside in a falsifiable policy or insight, rather than serialization of states.

## Narrow candidate claim and falsifiers

A candidate research question, not an established result:

> For a fixed pretrained recurrent detector and fixed causal observation budget, does an explicitly bounded controller that retains, resets, or restores the **complete** compatible execution state improve the trade-off between recovery after independently annotated normal drift and preservation of alarms during transient anomalies, beyond matched ordinary forgetting, simple resets, normalization and external-memory controls?

The claim concerns **intervention selection under ambiguous evidence**, not invention of state adaptation. It remains potentially backbone-independent. An xLSTM-specific claim requires an incremental effect not reproduced by matched LSTM/SSM state policies; architecture choice alone does not supply one.

A future authorization would need to fix these falsifiers before viewing results:

1. If periodic/window reset or a causal score/CUSUM/BOCPD trigger matches the proposed controller under the same history, reset count and latency, withdraw the policy-value claim.
2. If normalization-only or an external bank explains the gain, withdraw the recurrent-state mechanism claim.
3. If the controller shortens apparent recovery by accepting transient faults as normal or rewriting already emitted scores, reject the result.
4. If restoration benefits disappear after matching replay/history and coordinate compatibility, withdraw the bank-restoration claim.
5. If LSTM or a selective SSM matches the behavior under matched budgets, reframe as generic recurrent-state control; do not claim xLSTM-specific novelty.
6. If full text of RSI, U01, U02 or U03 reveals the same causal selection/operator and evaluation distinction, stop or narrow further.

No numerical thresholds, dataset labels, empirical effects or GO decision are invented here. The governing Issue/protocol must determine whether any subsequent empirical stage is authorized.
